# ROADMAP 2050 → 2026 — descente rapide du futur vers l'état réel

> **Comment lire** : on part de **2050** (le monde visé), puis on **descend par paliers courts** — 2045, 2040, 2035, 2030, 2028, 2027 — jusqu'à **aujourd'hui (2026-10-07)**. À chaque palier : *ce qui existe déjà*, *ce qui doit être construit*, *le moteur (qui porte quoi)*, *les décisions*.
> **Ancrages réels** : `constitution/00-vision.md` et `04-roadmap.md` (Phases 0→7) pour 2026-2027 ; `ANALYSE-V1-V5.md` (v1→v5) pour les étapes ; au-delà de ~2035, c'est de l'**horizon** (hypothèse assumée, marquée 🧭).
> **Légende certitude** : ✅ ancré (document/élément existant) · 🟡 plausible (extrapolation directe) · 🧭 horizon (vision).

## 2050 — Le « Semantic OS » a tenu 🧭

**Image** : une personne, une commune, une organisation demandent « comment faire X ? » — le système comprend, mobilise les connaissances, explore des solutions, conçoit, simule, **fabrique ou réalise**, puis observe le résultat et apprend. Explicitement **pas** un remplacement de NVIDIA/Google/Palantir/Autodesk : **la couche qui oriente, relie et orchestre**.

| Déjà existant (les germes, 2026) | Ce qui devrait être vrai en 2050 | Moteur porteur (dépôt/domaine) |
|---|---|---|
| La formulation : « Semantic Operating System for Human + Knowledge + World + Design + Action » | Une plateforme souveraine (FR/EU) avec ontologie publique et écosystème de modules | `COGNITORIUM` (vision) | 
| La boucle en 11 étapes (comprendre → … → apprendre du résultat) | La boucle tourne **en production**, à l'échelle d'un territoire/organisation | les 12 domaines |
| Le garde-fou éthique : « aucune fonctionnalité visant une personne physique » | Éthique devenue **exigence produit** (auditabilité, transparence) | D3/D12 |

**Jalon mesurable 2050** : un utilisateur non technique obtient une décision outillée (données + preuves + simulation + plan) sur un problème réel de son territoire, en boucle fermée, sans intervention d'expert.

## Chemin critique (la chaîne de dépendances qui commande tout)

```
Étape 0 (hygiène)
   └─> v1 : Core bi-temporel + HCSM contrat + interface/catalogue fusionnés
          └─> v2 : World + Human + Knowledge + Territory branchés
                 └─> v3 : Intel analytique + BTP + Learning + nexus_os
                        └─> v4 : Simulation + Cad + agents complets
                               └─> v5 : Fabrication + world model
```

**Trois règles qui font tenir la descente**
1. **Ne rien construire avant le Core** : chaque brique construite « à côté » reproduit les 5 mémoires éclatées actuelles.
2. **Une donnée, une source** : les 3 bases de connaissances, les 2 représentations cognitives et le fork watchtower se tranchent **avant** la migration.
3. **Contract-first** : tout branchement = un schéma d'échange versionné (leçon Palantir/World Monitor) et toute affirmation = une preuve datée (méthode Talbot).

**Ce qui invaliderait cette roadmap** : (a) décider que Cognitorium n'est pas une plateforme mais un produit mono-usage (alors v4/v5 disparaissent) ; (b) l'arrêt de la vitrine Polsia sans décision ; (c) la perte de `frontignan` (pas de dépôt) ; (d) un changement de priorité vers le seul domaine BTP (qui est un métier complet à lui seul).
