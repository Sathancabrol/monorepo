## 1. Audit avant installation
- Vérifier que E:\ai interface existe et l'espace libre. Inventorier les clones, Olympus Studio, X-Ray Mirror, ComfyUI, Python/Node, modèles et fichiers existants, OBS, FFmpeg et pilotes NVIDIA. Ne pas écraser ni déplacer des travaux non committés. Ne pas réinstaller les outils existants.
- Inspecter git status, HEAD et branches. Si un clone monorepo existe, fetch puis créer un worktree indépendant dans E:\ai interface\Olympus-Reality-Lite (nom alternatif si occupé). Sinon cloner la branche dans un sous-dossier neuf de E:\ai interface; ne jamais utiliser le dossier racine comme cible d'écrasement. Conserver toutes les autres versions.
- Comparer ce socle GitHub à la version Olympus la plus récente sur le disque, intégrer par petits commits sans perdre de modules. Ne pas remplacer aveuglément la version locale avancée.
## 2. Installer et valider
- Node >=20 compatible Win10; npm test depuis projects/olympus-studio. Corriger toute régression. Lancer npm start et vérifier http://127.0.0.1:8787.
- Vérifier le runtime MediaPipe déjà disponible, puis si nécessaire scripts/install-reality-pose.ps1 (licences/hashes, assets locaux, ne pas les committer). Tester le signal synthétique, caméra autorisée, squelette, silhouette, décor, masque tête, arrêt source, export PNG. Vérifier que la camera n'est pas ouverte deux fois dans LIVE et VFX. Tester l'absence d'assets sans crash.
- ComfyUI local : réutiliser installation et checkpoints, vérifier API 8188 et CUDA compatible Pascal sm_61 / Turing sm_75; ne pas installer un PyTorch qui exclut la GTX 1060. Si aucun modèle adapté, récupérer seulement SD-Turbo checkpoint complet (licence et provenance), ou alternative légère compatible; ne pas télécharger Wan 14B. Aucun cloud ni compte obligatoire. Garder un fallback graphique.
- Tester 256/320 puis 384/512 uniquement si stable. 4 étapes, denoise .5, CFG 1. Tester une image avant la boucle, relever nvidia-smi, latence, VRAM, RAM, FPS rendu, stabilité et OOM. Ne pas prétendre à du temps réel génératif si non mesuré. Si VRAM insuffisante tester lowvram, stable-diffusion.cpp Vulkan/CUDA et TAESD, ou SDXS réellement img2img; limiter téléchargements et durée.
- Reprendre les données X-Ray Mirror si le contrat local est disponible; ne pas inventer de port ou d'API. Ajouter tests d'interopérabilité. Priorité : même flux vidéo, pose/masques, compensation des mouvements, sortie OBS sans conflit, puis moteurs supplémentaires. Laisser les modules non testés explicitement signalés.

Reporter les tests, chemins absolus, versions, performances, limitations, espace utilisé, état Git et diff dans INSTALL_REPORT.md. Aucun secret, média utilisateur ou poids dans Git. Commit/push de la branche de travail après contrôle; pas de merge main automatique.
